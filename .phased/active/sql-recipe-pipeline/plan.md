# Context: wf/sql-recipe-pipeline
Parent: main
Mode: autonomous
Must not break: genro-sqlmigration never imports genro-sql — the dependency is one-way (genro-sql[migration] -> genro-sqlmigration)
Must not break: every SqlMigrationRenderer output passes genro_sqlmigration.StructureValidator (structure-1.0 is the contract)
Must not break: src/genro_sql/legacy/ stays untouched — it is the genropy-compat reference for a future importer
Must not break: semantic-plane attributes (name_*, group, caption_field, x_*, ...) never reach the normalized JSON

## Objective

Build the full recipe <-> database pipeline on the modern grammar: a genropy-like
`SqlBuilder` recipe with class-scoped grammar mixins, typed signatures and domain
validators; a `SqlMigrationRenderer` projecting the source tree into the normalized
`structure-1.0` JSON consumed by genro-sqlmigration (which creates/aligns real
databases); and the reverse path — normalized JSON -> source tree (`SqlModelReader`)
-> deterministic Python recipe (`SqlPythonEmitter`) — closed by round-trip tests
against SQLite and a live PostgreSQL. A grammar reference document is generated by
introspection.

## Global decisions (apply to every phase)

- **D1 — architecture**: one dialect, grammar organized in class mixins
  (`DbElements`, `SchemaElements`, `TableElements`, `ColumnElements`) composed into
  `SqlBuilder(...mixins..., BuilderBase)`. Subbuilder scope-switching was spiked and
  rejected: `collection_key` does not survive the dialect switch, name-keyed
  addressing (`db.public.author.id`) is lost (see notes.md).
- **D2 — semi-closed columns**: element signatures declare physical AND enumerated
  semantic parameters, typed. `**extra` is accepted at grammar level; the domain
  validator (Phase 3) requires every extra key to start with `x_` — anything else
  (e.g. a `dtypo=` typo) is a loud validation error listing the declared names.
- **D3 — indexed is sugar**: `indexed=True` on a column materializes a real index
  item in the projection (structure-1.0 has no `indexed` column attribute). Legacy
  parity rule adopted: a column carrying a `foreign_key=True` relation is always
  indexed (gnrpy orm_extractor behaviour).
- **D4 — composite FK**: in the grammar a multi-column FK is a `relation` on a
  `compositeColumn` (roadmap/05 §2.4). `SqlModelReader` synthesizes deterministic
  composites named `"_".join(columns)` for imported multi-column FKs; the target is
  implicit (`to="schema.table"`) when `related_columns` equals the target pkey,
  otherwise a target composite is synthesized with the same naming rule. A name
  collision with an existing column is a loud error.
- **D5 — types**: `dtype` is a `Literal` over the 23 codes of
  `genro_sqlmigration.structures.DTYPE_CODES`; `sql_type` is the native escape
  hatch and wins over dtype when present.
- **D6 — normalization parity**: the renderer applies the exact rules of
  `JsonStructureProducer`: pkey columns get `notnull='_auto_'`, a single-column pkey
  drops a redundant `unique`, absent dtype defaults to `'A'` if `size` else `'T'`,
  `clean_attributes` semantics come from the factories (never reimplemented).
- **D7 — emitter**: literal mode only. Deterministic output: variables for
  db/schema/table, canonical kwarg order (name first, physical, semantic, x_*),
  no structural hashes emitted as names, `# TODO` comment for preserved but
  unrepresentable features.
- **D8 — module layout**: new code lives in `src/genro_sql/modern/`:
  `elements.py` (grammar mixins), `builder.py` (SqlBuilder), `validators.py`,
  `migration.py` (SqlMigrationRenderer), `reader.py` (SqlModelReader),
  `emitter.py` (SqlPythonEmitter), `grammar_doc.py` (MD generator).
  `modern/renderer.py` (DDL placeholder) stays as is — DDL rendering is out of
  scope. Public API re-exported from `genro_sql` root `__init__.py`.
- **D9 — dependency direction**: `pyproject.toml` gains
  `[project.optional-dependencies] migration = ["genro-sqlmigration>=0.1.0"]`.
  Only `migration.py`/`reader.py`/test modules import `genro_sqlmigration`.
- **D10 — PG in the Done**: tests use `GNR_TEST_PG_HOST/PORT/USER/PASSWORD` env
  with defaults `127.0.0.1:5432`, user `postgres`, no password (verified reachable
  on this machine — PostgreSQL 16 via Homebrew). Test databases are named
  `test_genro_sql_<suffix>` and dropped in teardown. PG tests carry
  `@pytest.mark.postgresql`; they are part of the Done (they run, not skip).
- **D11 — contract tests**: authored at plan time under
  `.phased/active/sql-recipe-pipeline/tests/phase-N/`. Each phase copies its own
  tests verbatim into `tests/` in the repo tree at phase start and implements until
  green. Executable tests are byte-identical after the copy; skeletons keep name +
  `wf:contract:` lines verbatim and lose the red body. The contract is read-only
  for the child (contracts.md rules).
- **D12 — out of scope**: view, function, sequence, dbtype, trigger, eventTrigger
  disappear from the modern grammar (no empty slots); DDL renderer; GUI; the
  genropy live-model importer. They return in later work.

## Notes

- **Spike evidence (D1)**: a subbuilder-scoped grammar chain (db -> schema -> table
  -> column as registered dialects) was exercised on genro-builders 0.23.1 before
  planning. Containment and rendering work across the switch, but `collection_key`
  declared on an element does NOT key the children created inside the mounted
  sub-dialect (nodes come out `table_0`, `column_0` instead of name-keyed), so
  name addressing (`db.public.author.id`) breaks. Flat mixin composition keeps it.
- **`indexed` docstring bug inherited**: the pre-existing modern/elements.py
  docstring lists `indexed` among COL_JSON_KEYS; the contract has no such key.
  Phase 2 rewrites those docstrings; Phase 4 projects it per D3.
- **genro-builders is used from the bench venv** (editable, branch `wf/cookbook`,
  runtime 0.23.1). The cookbook branch only adds examples over `main` — no library
  difference. If `main` is checked out later, nothing here changes.
- **PG availability is an environment premise** of Phases 5 and 7 (D10). If the
  local server is down the run fails honestly at those phases; restart it and
  rerun (`brew services start postgresql@16`).
